# Gorps Evolution / Chaos Galaxy — continuous improvement

Owner: TMT Core Studios. Updated: 2026-10-12. This is the cross-run implementation backlog. Source, headless Luau, lint and build evidence do **not** establish Roblox Studio, device, multiplayer, persistence, art quality or publish readiness. [RELEASE_GATES.md](RELEASE_GATES.md) remains the acceptance contract.

## Resume procedure

1. Read fresh `origin/main`, recent commits, open work and the latest Actions run. Preserve concurrent changes; never force-push or replay an old tree over main.
2. Read this file and the release gates. First finish a failing/incomplete previous milestone. Record the previous implementation commit and its exact CI run here in the **next** consolidated implementation commit; a commit cannot contain its own SHA.
3. Select one coherent, highest-value confirmed defect. Prioritize startup and first-ten-minute playability. Reproduce suspected issues before changing behavior.
4. Implement actual code, meaningful regression coverage and the matching Studio test instructions. Run the relevant tests, Selene and Rojo; push one consolidated commit directly to main and inspect its actual Actions results.
5. Update issue status, verification limits and NEXT ACTION. Rotate deeper audits through the coverage table; do not repeat a full audit from scratch on every run or create content/commit spam.

No paid dependencies, player-value wagers, live publishing or Robux changes. Phase 5 requires real Studio/private-experience evidence and user approval. The existing hourly automation resumes from this file; this document itself does not schedule execution.

## Latest implemented milestone: GE-SAVE-03a — stale-session write protection

- Fresh baseline: [`a8d3825`](https://github.com/osohbayr1016/gorps-evolution/commit/a8d3825fefd3798f9dbab6039955b2af648c7bda). Its exact push [Actions run 38162884441](https://github.com/osohbayr1016/gorps-evolution/actions/runs/38162884441) completed successfully. That previous controller-focus milestone remains pending Studio/device acceptance.
- Confirmed P1 persistence defect: live `Data.load` used `GetAsync`, while `Data.save` ignored the current value passed to `UpdateAsync`. Two overlapping servers could therefore load the same profile and a stale server could overwrite newer coins, pets or inventory. Roblox documents this as a data-loss and item-duplication risk in player-data systems.
- Implemented: live loads now atomically claim a reserved persisted session token through `UpdateAsync`; active foreign sessions fail closed with a specific retry message. Autosaves validate and renew a five-minute lease, stale writers cancel instead of overwriting, and final leave/shutdown writes remove ownership. Same-token release retries are idempotent after an unknown response, while a server that was superseded and later sees an unlocked profile still cannot write. Legacy tables migrate without changing progression; malformed saved values/locks fail closed. Unpublished Studio profiles remain isolated and unsaved.
- Regression: `scripts/test_session_policy.luau` executes the pure production policy and passes 31 assertions covering legacy migration, deep-copy preservation, active-lock refusal, renewal, exact-expiry takeover, stale-writer rejection, final release, unknown-outcome retry, rejoin and corrupt-data refusal. CI also requires `Data` and `SessionPolicy` in the Rojo package and static ownership wiring.
- Verification boundary: pure policy, lint and package checks do not call Roblox DataStoreService or reproduce an actual cross-server disconnect, throttle, crash or unknown write outcome. `STUDIO_QA.md` defines the private-published rapid-rejoin test; public persistence remains unaccepted until that evidence exists.
